\section{Executive summary}

Researchers who combine the references of several papers (for a survey, a
thesis or a group library) find the same work under different citation keys,
with titles, author lists and venues written differently.  Our stakeholder,
Prof.\ Ashrujit Ghoshal (CSE, IIT Madras), reconciles these by hand and has to
redo the check every time a paper is added.

We shipped a Java~21 merge engine served as one JAR with a web app and a CLI.
A user uploads several \texttt{.bib} files or papers' PDFs, answers ``same
paper / not the same'' for the few borderline pairs, and downloads one
\texttt{merged.bib}; old keys survive as biblatex \texttt{ids} aliases, so
existing \verb|\cite|s keep working, and a paper is added later by uploading
the earlier \texttt{merged.bib} with it.  218 automated tests pass, and runs
on real IACR ePrint and published IEEE papers gave no false merges.  Scope
change since the proposal: we added PDF input; storing decisions between
sessions was dropped.

Stakeholder verdict: \emph{pending}.  We have asked Prof.\ Ghoshal for a final
demo; a recorded demo is in the Drive folder, and the live one will be added.

\textbf{One substantive help.}
Claude Code drafted PDF input, \texttt{pdf/PdfReferenceExtractor.java} and
\texttt{pdf/ReferenceParser.java}, with test tables for IEEE, Springer LNCS and ACM reference styles; it read
18 of 18 references from our compiled test PDFs as written and needed only
small fixes for published two-column papers (\texttt{4711e78}, \texttt{8fbbfcd}).

\textbf{One substantive failure caught in review.}
The AI-written key minter could mint a new key equal to another entry's
retired key, so \verb|\cite{oldkey}| would silently resolve to a different
paper; each module passed its own tests, and our boundary bug hunt caught it
before it reached \texttt{main} (\texttt{d6b9b9b}): \emph{plausibly wrong} code
silently corrupting persistent user data, in the terms of Module 8
(Limitations, Evaluation and Best Practices).

\textbf{Net-effect sentence.}
Net help: the AI wrote most first drafts, and the tests and real-data runs
we put around its output caught all six bugs in our debugging log.

\section{Known limitations}

\begin{itemize}[leftmargin=*,nosep]
  \item \textbf{Scale.}  Blocking compares every pair of records: 2,000 records
        take 29\,s and 1.5\,GB, and the design target of 10,000 records in
        10\,s is not met.
  \item \textbf{No memory between sessions.}  Reviewer answers last one browser
        session; adding a paper later works only if the user keeps and
        re-uploads the earlier \texttt{merged.bib}.
  \item \textbf{PDF input is approximate.}  Scanned PDFs without a text layer
        give no references; on published IEEE papers 1 of 26 references came
        out with wrong fields, so fuzzy PDF matches go to review, never merge.
\end{itemize}
